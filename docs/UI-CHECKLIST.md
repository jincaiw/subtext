# UI 检查清单

这份文档记录的是**本项目实际踩过的界面缺陷**，不是一般性的设计原则。每一条都能指到一个具体的
文件、一次提交、一张截图。改界面之前读一遍，能省掉一轮「截图才发现」。

一般性的设计规则在 gpui-kit 的 Design Guides 里，这里不重复。

---

## 1. 放进列里的控件，会沿交叉轴被拉满

**症状**：按钮变成整行宽、复选框的勾和文字被拉开很远、只有一个字段的行看起来像标题栏。

**原因**：`v_flex()` 的交叉轴默认是 stretch，直接挂上去的子元素会吃掉整行宽度。

**正确写法**：要「按钮只有标签那么宽」，就把它放进一行：

```rust
v_flex()
    .child(h_flex().child(Button::new("x").label("Do it")))
```

**本项目踩过**：*Manage Warnings…*（§22.19）、*Edit List…*（§22.19）、*Learn More…*（§22.20）。
三处都是同一个错误，隔了两次提交才发现第二次。

**反例**：`button.w_full()` 是**故意的**——列表行（`pick_list_with_gaps`）要它整行可点。

---

## 2. 定宽容器里并排放不下，右半会被静默裁掉

**症状**：`End:` 字段不见了、`Hexadecimal` 只剩 `Hexade`、`#000000` 只剩 `#00`。

**原因**：`Dialog::w()` 是硬宽度，内容超出去就被裁——**没有省略号，没有滚动，什么提示都没有**。

**检查方法**：一个「标签 + 字段」对大约 160 px。`Dialog::w()` 设的宽度减 32 px 内边距，能放几对
自己算。放不下就改成上下排。

**本项目踩过**：Custom Surround（两个字段并排，§22.18）、Edit Color Code（标签列 + 值，§22.18）。

**这条最危险**，因为被裁掉的东西**看起来像不存在**——用户不会报「少了一个字段」，只会觉得这个功能
就是这样。

---

## 3. 固定高度超过可用空间，把后面的东西顶出窗口

**症状**：底部的按钮只露出上边缘；要滚一下才能发现那里有东西。

**原因**：面板整体是可滚动的，一个 `max_h(28rem)` 的列表会把下面的行推到窗口外——滚动条能到，
但**默认视图里看不见**。

**正确写法**：在一个可滚动的页面里，列表的 `max_h` 要按「窗口默认高度减去上面和下面的固定部分」
来定，不要按「列表本身能长多高」。

**本项目踩过**：Shortcuts 的列表（28 rem → 22 rem，§22.20）。

**相关**：`window_bounds` 没设时会继承主窗口尺寸。设置窗口因此开成 1536 宽、内容只用 530
（§22.19）。**新开一个窗口就要给它尺寸**。

---

## 4. 同一个面板里的标签列，要么都走 helper，要么都不走

**症状**：一行的标签贴在面板左边缘，上下几行都右对齐在 12 rem 处。

**原因**：`field()` 给标签一个 `w(rems(12.)).justify_end()` 的列，裸写的 `div("Label:")` 没有。

**正确写法**：新增一行就用 `field()`；确实需要另写结构时，把那一列照抄过去（`settings_window.rs`
的 `LABEL_COLUMN`）。

**本项目踩过**：Edit 页的 `Indent width:`（§22.20）。

**例外**：子项的标签本来就该缩进（`Delay:` 用 `.pl_4()` 挂在父项下面），那不是对齐错误。

---

## 5. 组件库硬编码的地方，不要对着干

这几处改不动，只能在别处绕。**先读实现再下结论**：本表里曾有一条「`DialogFooter` 只渲染一个按钮」
是错的 —— 读一眼 `dialog/footer.rs` 就知道全部子元素都渲染，只是 `DialogClose` 占了整行（§22.24）：

| 组件 | 硬编码 | 绕法 |
| --- | --- | --- |
| `Button` | 内部 `justify_center()` | 列表行要左对齐就用 `.child(div().w_full().child(label))` 代替 `.label()`（§22.19） |
| `DialogClose` | 渲染成 `div().size_full()`，在 footer 里**占满整行** | 同一行还有别的按钮就别用它，用普通 `Button` + `window.close_dialog(cx)`；只有「`DialogClose` + `DialogAction`」这一对（各占一半）才是组件库的用法（§22.24） |
| `ManagedTooltipExt` | `pub(crate)` | `div` 挂不上 tooltip；需要 tooltip 就换成 `Button`（§22.17） |
| `Checkbox` | label 宽度跟内容 | 父容器太窄时文字会换行，不是 bug 但要看得见 |

## 6. `ghost()` 是「没有边框」，不是「低调」

**症状**：两个图标按钮看起来像两个散落的符号，不像能点的东西。

**原因**：`.ghost()` 去掉背景与边框，只剩图标。它适合「工具栏里已经明确的次要动作」，
不适合「一个列表下面唯一的那两个操作」。

**正确写法**：功能性按钮用默认（outline）样式；`ghost` 留给确实不需要边界的地方。

**本项目踩过**：Snippets 页的 `+` / `−`（§22.21）。

---

## 7. 界面文案不是 Markdown

**症状**：设置页里出现 `` `cot` ``、`` `subtext FILE` ``。

**原因**：从 README 抄文案时把反引号一起抄了。

**正确写法**：引号用弯引号 `“ ”`，或者直接不加引号。

**同样的要求适用于「说的对不对」**：说明文字描述的是应用实际做的事，不是上游做的事。上游的
自动保存说明承诺了版本历史，SubText 没有这个功能，那句话就必须写成「尚未实现」并说清楚现状
（§22.60）。抄上游文案时，先确认这一句在本项目里成立。

**本项目踩过**：Integration 页的 command-line 说明（§22.20）、General 页的自动保存说明（§22.60）。

---

## 8. 禁用态要覆盖组合控件的每一部分

**症状**：步进器的 − / + 是灰的，中间的数字还是黑的 —— 夹在两个灰按钮中间，读起来像一个
还活着的输入框。

**原因**：`stepper_when(…, enabled, …)` 把 `enabled` 只传给了两个按钮，值格是另一个 `div`，
要单独跟着变灰。

**正确写法**：组合控件（步进器、标签 + 字段、复选框 + 说明）的禁用态，把同一份 `enabled`
作用到**每个**可见部件上；标签与值用 `muted_foreground`，与上游禁用的 `TextField` 一致。

**本项目踩过**：Integration 页的 *Port:* 行（§22.60）。

---

## 9. 图标按名字挑，要打开 SVG 看一眼

**症状**：工具栏的 Share 按钮画出来是三个圆点连成的网络，不是 macOS 那个「方框 + 向上箭头」。

**原因**：`IconName` 的名字来自 Lucide，很多是近义词。`Share` 是方框加向上箭头（与
`NSImage.shareTemplateName` 同形），`Share2` 是节点网络 —— 两个名字看起来都能当「分享」，
只有画出来才知道差多远。

**正确写法**：选图标时打开 `gpui-kit-assets-*/assets/icons/<name>.svg` 看 path，或者与参考
窗口的截图并排比。同一份工具栏里，`toolbar.rs` 的 `ToolbarItemId::Share` 早就映射成
`Share`，`workspace.rs` 手绘的那个按钮却用了 `Share2`，两处不一致本身就是线索。

**本项目踩过**：工具栏 Share 项（`workspace.rs`）。

---

## 10. 长下拉菜单不加 `scrollable`，下半截既看不见也够不着

**症状**：右上角语法框点开，七十种语法只画到屏幕底为止，后面的没有滚动条、滚轮也没反应，
只能看到前面的一小段。编码、字体、片段语法等其他长列表是同一个毛病。

**原因**：gpui-kit 的 `PopupMenu` 默认**不裁剪也不滚动**。`.max_h()` 只是把高度记下来，
真正生效要 `.scrollable(true)` —— 它才加 `max_h` + `overflow_y_scroll` + 竖向滚动条
（`gpui-component-0.8.1/src/menu/popup_menu.rs:1511`）。只写 `.max_h()` 的菜单看起来
像「限高了」，其实什么都没发生。AppKit 的 `NSMenu` 超过屏幕会自动滚动，所以这里不加就是
与上游不一致。

**正确写法**：条目不设上限、会随用户环境增长的下拉菜单，收尾一律 `.scrollable(true)`。
项目里 `encoding_list_sheet.rs` 的加编码菜单和 `popup_pick_list` 已经是这么做的，可以对照。

**本项目踩过**：工具栏语法框、状态栏编码列表、Appearance 面板的字体族、片段面板的两处语法
选择（§22.63）。`crates/subtext-app/tests/ui.rs` 的
`the_syntax_menu_scrolls_to_the_syntaxes_past_the_fold` 会打开菜单并滚轮，去掉
`scrollable(true)` 就红。

## 怎么验证

0. 截图里**有没有该看的那个东西**？窗口列表里 `onscreen=true` 才算上了屏 —— 浮动面板在应用非前台时
   是 `false`，截出来一片空白，而且不报错。


冒烟只能证明「打开不崩」，证明不了「画得对」：

```bash
# 打开第 n 个面板并停住（n 的取值见 tools/peek-panel.sh 的注释）
tools/peek-panel.sh 14 Shortcuts /tmp/shortcuts.png   # 真窗口；设置窗口的标题是当前面板名
tools/peek-overlay.sh 0 /tmp/surround.png             # 对话框（在窗口之上的独立层）
```

两条命令的区别是必须的，不是风格问题：`screencapture -l <windowid>` **截不到对话框**，因为
`window.open_dialog` 把它画在窗口之上的独立合成层里，而 `-l` 截的是窗口自己的 backing store。
用错命令的结果是一张「什么都没有发生」的正常截图。

同样地，脚本里 `pkill` 之后要**轮询 `pgrep` 直到进程真的消失**——`pkill` 返回不等于进程已退出，
截到的是上一轮的窗口，而三次不同的源码改动会产出**逐字节相同**的截图。这两条都真的发生过。

## 一份改动前的自检

1. 这一屏里的按钮，有没有直接挂在 `v_flex` 上的？（规则 1）
2. 这一屏里最宽的一行，在**默认窗口宽度**下放得下吗？（规则 2、3）
3. 新窗口设 `window_bounds` 了吗？（规则 3）
4. 新的标签行走了 `field()` 吗？（规则 4）
5. 功能性按钮是不是误用了 `ghost()`？（规则 6）
6. 界面上的文案有反引号、Markdown 强调符号吗？（规则 7）
7. footer / 行里有没有 `DialogClose` 这类「自己会 `size_full()`」的组件和固定宽度控件并排？（规则 5）
8. 截一张图看了吗？看的是**该看的那个东西**吗？（验证）
